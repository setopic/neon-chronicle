# 物語の文書を既定の種別で書く

- 日付: 2026-10-18
- 状態: stable

## 背景

ゲームの世界観・流れ・主なシステムは、企画メモ（claude.aiの文書）にしか無かった。`docs/`にはゲームの全体構成（[ARCH-01](../10-architecture/arch-01-game-overview.md)）しか無く、仕事やイベントを足すときに、用語と前提がずれるおそれがあった（issue #4）。

決める必要があったのは2つである。企画メモのどこまでをドメインの層に移すかと、ストーリーの文書をどの種別で書くかである。ノード種別は、リポジトリの根に`graph.toml`を置くと差し替えられる。

## 決定

1. 企画メモのうち、実装済みのシステムと世界観をドメインの層に移す。世界観は[DOM-01](../20-domain/dom-01-world.md)、周と体は[DOM-02](../20-domain/dom-02-life-and-body.md)、仕事とスキルは[DOM-03](../20-domain/dom-03-jobs-and-skills.md)、インプラントは[DOM-04](../20-domain/dom-04-implants.md)、転生と永続強化は[DOM-05](../20-domain/dom-05-rebirth.md)に書く。
2. まだ実装していないイベント・クロニクルの物語文・ストーリーとエンディングは、いま移さない。それぞれのissue（#5・#6・#7）で決めたときに、ドメインノードとして書く。
3. 画面の構成と見た目は、ドメインの層に移さない。概念ではなく、実装の詳細だからである。
4. `graph.toml`は置かず、既定の種別を使う。ストーリーの概念（記憶の断片やエンディングの条件など）も、`domain`のノードとして書く。
5. ここから先は、`docs/`の文書を正しいものとして扱う。企画メモは書いた時点の記録として残し、直さない。

## 理由

いま書く物語は、世界観の前提が数行あるだけである。人物や場所が何十も出る題材ではないので、ドメインの層の「定義」と「用語」で書き切れる。

ドメインノードに書くと、用語表が`G013`・`G022`の検査を受け、ドメインの目次の「用語の一覧」にも載る。イベントやクロニクルの物語文は、仕事・周・体の用語を使って組み立てるので、システムの用語と同じ表にあるほうが食い違いに気づける。

まだ決めていないものを移さないのは、決まる前に書くと、決めた記録ではなく揺れた記録になるからである（META-05）。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| `graph.toml`で物語の種別（`story`など）を足す | `graph.toml`に種別を1つでも書くと、既定の5つの種別も書き直すことになる。全ノードに関わる変更なのに、物語として書く量はまだ数行しかない |
| 企画メモを丸ごとドメインの層に写す | イベントやエンディングのように、まだ決めていないものまで決まったように見える。画面の構成は概念ではない |
| 世界観を[ARCH-01](../10-architecture/arch-01-game-overview.md)に書く | アーキテクチャの層は構成と責務を書く場所で、用語の検査（`G013`）も届かない |
| 企画メモを正しいものとして残し、`docs/`は要約にとどめる | 2か所に同じことを書き、どちらを直せばよいか分からなくなる。企画メモは`check`の検査を受けない |

## 影響

DOM-01〜DOM-05が新しくでき、ゲームの用語がドメインの目次の「用語の一覧」に集まる。#5〜#7で書くノードは、これらに`depends_on`で依存する。

`game/scripts/game_state.gd`のモジュールの説明に、DOM-02〜DOM-05のidを書く。

## 見直しの条件

ストーリーで書く人物・場所・出来事のノードが、ゲームのシステムのノードより多くなったら、`graph.toml`で物語の種別を分けることを見直す。
