# 放っておく間のログに、仕事の区画の噂を流す

- 日付: 2026-10-20
- 状態: stable

## 背景

本作の文書には、街の歴史・勢力・場所・住民の暮らしまで書いてある（DOM-14〜DOM-19）。遊んでいてそれに触れるのは、イベントと資料が主である。仕事を放っておく間のログには、街の様子を伝える文が少なかった（issue #144）。

『VA-11 Hall-A』は、大きな事件を店に来る客の会話から伝えている。issueでは、噂の出どころと頻度とログに占める量、評判や話の進みで噂を変えるか、資料とどう関わらせるかを決めることにしていた。作者からは、推奨の案で進めてよいと言われている。

## 決定

1. 噂は、主人公が就いている仕事の、[仕事の区画](../20-domain/dom-24-job-districts-and-identity.md)の住人が話す。仕事の区画は、仕事のデータにある`district`を使う。
2. 同じ仕事を2分続けるごとに、噂を1つログに出す。新しい乱数は足さない。仕事を替えると、2分を数え直す。
3. 閉じていた時間を進めている間は、噂を出さない。
4. 勢力の評判が3以上か-3以下のとき、その勢力についての噂が出るようになる。資料の追記が出ていると、その追記に合わせた噂も出るようになる。噂の出る評判か噂の出る追記を持つ噂がその周にまだ聞いていないものとして残っていれば、そちらを先に出す。
5. 噂は資料に書き足さない。資料の追記は、噂の条件にだけ使う。
6. 噂は`game/data/rumors.json`に置き、文は`game/lang/`に置く。新しいドメインノード[DOM-33](../20-domain/dom-33-city-rumors.md)に書く。

## 理由

仕事の区画の住人に話させたのは、仕事を替えると聞こえる噂が替わり、区画ごとの暮らしの違いが伝わるからである。仕事のデータにある区画をそのまま使えるので、データに新しい値を足さずに済む。

決まった間隔で出すのは、ログに占める量を見積もれるようにするためである。2分ごとなら、運び屋の仕事の24回に1行ほどで、スキルのレベルが上がった行やイベントの行を押し流さない。乱数を足さない線は、イベントの起きやすさを決めた[ADR-0045](./adr-0045-event-waves.md)と同じである。

閉じていた時間に出さないのは、8時間分を進めると噂だけでログの上限の50行を超え、閉じていた間の成果の行が流れてしまうからである。

評判で噂を変えるのは、勢力が主人公をどう見ているかを、選ぶ条件を持つ選択肢が出る前から知らせるためである。桜井政博さんの言う、どちらかに肩入れする楽しみを、選んだ側の住人の声で返す。

噂を資料に書き足さないのは、資料の追記を出す決まり（記憶の断片かイベントで分かったことだけを出す）を変えずに済むからである。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| 決まった1人（屋台の店主など）に噂を話させる | 企業の縄張りの噂を下層街の人が話すことになり、区画ごとの違いが出ない |
| 話し手を決めず、街全体の噂として出す | 仕事を替えても聞こえる噂が変わらない |
| 1秒ごとの確率で噂を出す | ログに占める量がばらつき、続けて出ることもある |
| ひと息つける間にだけ噂を出す | 危ない目に遭わない周では、噂がほとんど出ない |
| 閉じていた間も同じ頻度で噂を出す | 噂だけでログが埋まり、閉じていた間の成果の行が流れる |
| 噂を聞くと、資料に追記が加わる | 資料の追記を出す決まりが2通りになる |

## 影響

DOM-33を起こし、噂・噂の出る評判・噂の出る追記を定義する。`game_state.gd`は、その周に聞いた噂をセーブに書き、前の版のセーブはまだ噂を聞いていないものとして読む。`game/ci/check_data.py`は、噂が指す仕事の区画・勢力・追記と、文のキーがあるかを確かめる。`game/ci/away.gd`は、閉じていた間に噂が出ないことと、評判の条件の付いた噂が先に出ることを確かめる。

## 見直しの条件

噂が同じものばかりに聞こえるという声が出たら、噂の数か2分の間隔を見直す。ログが噂で読みにくいという声が出たら、間隔を延ばすか、噂を別の欄に出す。
