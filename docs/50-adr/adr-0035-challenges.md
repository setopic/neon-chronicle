# 転生のときに縛りを1つ選び、守り通せば記憶ポイントを上乗せする

- 日付: 2026-10-20
- 状態: stable

## 背景

終盤は、最も強い体・稼げる仕事・高い選択肢が決まり、周ごとの違いが出にくかった（issue #82）。遊ぶ人が自分で条件を課して周を始める仕組みが無かった。

issueでは、縛りの種類と果たしたときの報酬、いつから選べるかの2つを決めることにしていた。作者からは、推奨の案で進めてよいと言われている。

## 決定

1. 縛りを3つ置く。値は`game/data/challenges.json`に置き、MODで足せる。

   | 縛り | 守る条件 | 縛りの上乗せの割合 |
   | --- | --- | --- |
   | インプラントを買わない | その周にインプラントを1つも買わない | 0.3 |
   | 仕事を変えない | 最初に就いた仕事から、ほかの仕事に移らない | 0.3 |
   | 安全な選択肢を選ばない | 選ぶ条件のある選択肢を選べるイベントで、選ぶ条件の無い選択肢を選ばない | 0.5 |

2. 縛りは、転生の画面で、体の種類を選ぶ前に1つ選ぶ。選ばなくてもよい。第1周には縛りが無く、第2周から選べる。
3. 縛りを選んでも、操作は止めない。守る条件に反する操作をすると、その周の縛りを破ったことになり、ログに出す。破ったあとは、周の終わりまで戻らない。
4. 縛りを守り通した周は、周の終わりに得る記憶ポイントに縛りの上乗せを足す。式は`max(1, round(周の終わりに得る記憶ポイント × 縛りの上乗せの割合))`とし、ジンの依頼の上乗せと同じく、上乗せを足す前の記憶ポイントに掛ける。
5. 転生の画面の「記憶ポイント +N」の行に、縛りの上乗せの分を添える。周の間は、体の状態の欄に、縛りの名前と、守っているか破ったかを出す。
6. 縛りを守り通した周の記録には、縛りのidを残す。記録の物語文の後ろに、守った縛りを1句で足す。
7. 縛りは、新しいドメインノード[DOM-21](../20-domain/dom-21-challenges.md)に書く。

## 理由

3つの縛りは、終盤に決まりやすい3つの最適解（インプラントを買えるだけ買う、稼げる仕事に移る、条件を満たした高い選択肢を選ぶ）に1つずつ当てた。安全な選択肢を選ばない縛りは、イベントで耐久を大きく減らすことがあり、周が早く終わりやすいので、上乗せを大きくした。

操作を止めずに破ったことにしたのは、周の途中で縛りをやめる自由を残すためである。止めると、選ぶ条件のある選択肢をどれも選べないイベントで先へ進めなくなる。

第2周から選べるようにしたのは、第1周は遊び方を覚える周だからである。永続強化や記憶の断片の数を条件にすると、条件の値を決めることになる。

上乗せを依頼と同じ形にしたのは、転生の画面と記憶ポイントの式に新しい形を足さないためである。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| 縛りに反する操作をできないようにする | 選ぶ条件のある選択肢をどれも選べないイベントで、先へ進めなくなる |
| 縛りを2つ以上重ねられるようにする | 上乗せの重ね方を決めることになる。1つで周ごとの違いは作れる |
| 報酬をクロニクルの称号だけにする | 記憶ポイントに効かないと、縛りを選ぶ理由が弱い |
| 縛りを守った周の数で、永続強化を開く | 開く永続強化の中身を決めることになる |
| 記憶の断片が1つ戻ってから選べるようにする | 条件の値を決めることになる。第1周を除けば足りる |
| 縛りの上乗せを、依頼の上乗せのあとの記憶ポイントに掛ける | 上乗せどうしが掛け合わさり、釣り合いが2つの値で決まる |

## 影響

DOM-21を新しく起こし、縛り・守る条件・縛りの上乗せを定義する。周に縛りと縛りを破ったかの属性を足し、記録に守った縛りの属性を足す。

`game_state.gd`は、周の縛りと破ったかどうかをセーブに書く。前の版のセーブは縛りの無い周として読む。転生の画面に縛りを選ぶ欄を足す。`playthrough.gd`は縛りを選ばない。

## 見直しの条件

どれか1つの縛りばかりが選ばれるようになったら、上乗せの割合を決め直す。縛りを重ねたいという声が出たら、上乗せの重ね方を決める。
