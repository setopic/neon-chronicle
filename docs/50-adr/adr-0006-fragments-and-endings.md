# 記憶の断片を順に戻し、最後の仕事の選択でエンディングを分ける

- 日付: 2026-10-18
- 状態: deprecated（[ADR-0046](./adr-0046-third-ending.md)が置き換えた）

## 背景

企画メモでは、転生のたびに記憶の断片が戻り、企業の中枢サーバーで本当の体を取り戻すことを最終目標にしていた。ゲームには終わりが無く、[DOM-01](../20-domain/dom-01-world.md)の最終目標にたどり着く道も無かった（issue #7）。

決める必要があったのは、記憶の断片が戻る条件と、エンディングの数である。あわせて、エンディングへの入り方と、エンディングのあとに遊び続けられるかも決めた。

## 決定

1. 記憶の断片を5つ置き、決まった順に戻す。断片ごとに、スキルのレベルの条件を付ける。周が終わったとき、その周の終わりのスキルのレベルが次の断片の条件を満たしていれば、その断片が戻る。
2. 断片がすべて戻ると、最後の仕事「中枢サーバーへの侵入」に就ける。この仕事の間にだけ起きるイベント「中枢の扉」に、エンディングの選択肢を2つ置く。選んだ選択肢で、エンディングが「本当の体」と「ネットの亡霊」に分かれる。
3. エンディングの選択肢を選ぶと、その周が終わる。エンディングの画面を見せたあとは、ふつうの転生の画面に移り、転生して遊び続けられる。たどり着いたエンディングは記録に残し、クロニクルから数える。
4. 断片の条件の数値は、最初から最後まで約1時間で遊べるように決める。決まった手順で自動で遊ぶ`game/ci/playthrough.gd`では、約45分（6〜7周）でエンディングにたどり着く。CIでもこれを回し、たどり着かなければ失敗とする。
5. 断片とエンディングはデータとして`game/data/story.json`に置き、表示文は言語ファイルのキー`fragment.<id>.name`・`.desc`と`ending.<id>.name`・`.desc`・`.chronicle`に置く。

## 理由

断片の条件をスキルのレベルにしたのは、周ごとに違う仕事を選ぶ理由になるからである。条件が格闘・交渉・ハッキングに散らばっているので、同じ仕事だけを続けていると次の断片が戻らない。周の番号や記憶ポイントの累計を条件にすると、周を重ねるだけで戻り、プレイヤーの選び方と関係が無くなる。

順に戻すのは、断片の文を順に読むと話がつながるように書けるからである。どの順で戻ってもよいことにすると、どの断片も単独で読めるように書く必要がある。

エンディングの入り方をイベントの選択肢にしたのは、イベントの仕組み（[DOM-06](../20-domain/dom-06-events.md)）にそのまま乗るからである。2つに分けたのは、最後に主人公の選択を1つ残すためである。1つでは最後の選択肢が1つしか無くなり、3つ以上にすると、分かれ方を決める条件をもう1つ作ることになる。

エンディングのあとも遊べるようにしたのは、もう一方のエンディングを見たいプレイヤーが、最初からやり直さずに済むからである。たどり着いたエンディングを記録から数えるので、新しく持つ状態は戻った記憶の断片だけで済む。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| 周の番号で断片を戻す（第3周、第6周…） | 周を重ねるだけで戻り、どの仕事を選ぶかと関係が無くなる |
| 記憶ポイントの累計で断片を戻す | 記憶ポイントは永続強化に使うので、使ったかどうかで戻る時期がずれる。累計を別に数えると、見えない数が1つ増える |
| 断片がすべて戻った時点で、自動でエンディングにする | 最後に主人公が選ぶ場面が無く、エンディングを分けられない |
| エンディングを1つにする | 最後の選択が無くなる。分け方は選択肢を1つ足すだけで作れる |
| エンディングのあとは最初からやり直すしかない | もう一方のエンディングを見るために、クロニクルと永続強化を捨てることになる |

## 影響

[DOM-08](../20-domain/dom-08-memory-fragments-and-endings.md)ができる。[DOM-01](../20-domain/dom-01-world.md)の最終目標までの筋書きと、企業がしたことの分かり方は、DOM-08が決めることになる。[ARCH-01](../10-architecture/arch-01-game-overview.md)の未決事項からストーリーが外れ、CIに通しで遊ぶ検査が加わる。

`game/data/story.json`ができる。仕事に`needs_all_fragments`、選択肢に`ending`の項目が加わる。セーブには`fragments`（戻った断片のid）と`last_fragments`（直前の周の終わりに戻った断片のid）が、記録ごとに`ending`が加わる。#7より前のセーブはこれらを持たないので、空として読む。

断片やエンディングを足すMODは、`story.json`と同じ形で項目を置き、言語ファイルにキーを置く。断片はデータを読んだ順に戻るので、MODの断片は本体の断片のあとに戻る。

## 見直しの条件

実際に遊んだ人が、エンディングまで1時間を大きく超える、または断片が戻らずに止まると感じたら、断片の条件を見直す。エンディングを3つ以上にしたくなったら、分かれ方の条件を見直す。
