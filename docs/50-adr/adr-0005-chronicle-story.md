# クロニクルの物語文を仕事と選択と倒れた理由から組み立てる

- 日付: 2026-10-18
- 状態: stable

## 背景

企画メモでは、過去の周を「3周目：路地裏の運び屋として生き、組織の裏切りで倒れた」のように残すことにしていた。クロニクルには主な仕事と数値しか残らず、イベントで選んだことも記録に残らなかった（issue #6）。

決める必要があったのは、物語文を何から組み立てるか、クロニクルを集めたときのボーナス、画面での見せ方の3つである。

## 決定

1. 物語文は、主な仕事の句・その周で最後に選んだ選択肢の句・倒れた理由の句をつないで作る。倒れた理由は、選択肢の結果で耐久が0になったときはそのイベントの名前を使い、劣化のときは「体の限界」とする。周を終わらせた選択肢は、最後に選んだ選択肢には入れない。
2. 記録には文を残さず、仕事・選択肢・イベントのidを残す。文は表示するたびに、いまの言語で組み立てる。句は言語ファイルのキー`job.<id>.chronicle`と`event.<id>.<選択肢>.chronicle`に置き、つなぎ方は`chronicle.story`などのキーに置く。
3. クロニクルに残った選択肢の種類ごとに、経験の効果を0.02足す。同じ選択肢は何度残っても1つと数え、いまのデータに無いものは数えない。
4. 転生の画面では、終わった周の物語文を数値の下に出す。クロニクルの欄は全件をスクロールで見せ、各記録は物語文を主にして、数値をその下に小さく出す。

## 理由

主な仕事は記録に既にあり、倒れた理由はイベントで耐久が0になったかどうかで決まるので、どちらも新しく集める情報がほとんど要らない。選択肢を1つ入れると、同じ仕事の周でも物語が変わる。最後の1つにしたのは、文の長さを一定に保つためである。

idで残すのは、ログと同じく、言語を切り替えたときに過去の記録も読み直せるようにするためである。MODで言語を足しても、句のキーを足せば過去の記録がその言語で読める。

ボーナスを選択肢の種類に結びつけると、違う選択を試すほど得になり、物語の幅を集める動機になる。件数に結びつけると、周を重ねるだけで増え、物語の中身とは関係が無くなる。経験の効果にしたのは、既にある効果の足し合わせに乗るからである（[DOM-03](../20-domain/dom-03-jobs-and-skills.md)）。いまの選択肢は15種類で、すべて集めると経験の効果は0.3になり、永続強化の「記憶の残響」1レベル（0.25）と同じくらいになる。

物語文は1件で2〜3行になり、5件を並べると転生の画面が縦に収まらなかった。そのため、全件をスクロールで見せる。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| 物語文を主な仕事と倒れた理由だけで作る | イベントで選んだことが物語に残らず、同じ仕事の周がすべて同じ文になる |
| その周で選んだ選択肢をすべて並べる | 1周に3回前後選ぶので文が長くなり、周ごとの長さもばらつく |
| 記録に文そのものを残す | 言語を切り替えたとき、過去の記録が元の言語のままになる |
| 記録の件数ごとに稼ぎを増やす | 周を重ねるだけで増え、物語を集めることと関係が無くなる |
| ボーナスを入れない | issueで決めることに挙がっており、集める動機が無いとクロニクルを読む理由が薄い |

## 影響

[DOM-07](../20-domain/dom-07-chronicle-story.md)ができる。[ARCH-01](../10-architecture/arch-01-game-overview.md)の未決事項から、クロニクルの物語文が外れる。

セーブには、記録ごとに`deed`（`<イベント>.<選択肢>`）と`end`（イベントのid）が、周ごとの状態に`last_deed`が加わる。#6より前のセーブの記録はこれらを持たないので、空として読む。

イベントを足すMODは、選択肢ごとに`event.<id>.<選択肢>.chronicle`の句も置く。仕事を足すMODは`job.<id>.chronicle`を置く。CIの`check_data.py`が、本体のデータについてこの句の抜けを確かめる。

## 見直しの条件

記録に残った選択肢による経験の効果が、ほかの効果より強すぎる、または弱すぎると感じたら、0.02を見直す。イベントの数が増えて上限が大きくなりすぎたときも見直す。
