# 転生のときに4種類の体から1つを選ぶ

- 日付: 2026-10-18
- 状態: deprecated（[ADR-0032](./adr-0032-body-quality-and-memory-software.md)が置き換えた）

## 背景

周ごとに新しい体で目覚めるが、どの体も同じで、周の始まりに選ぶものが無かった（issue #36）。[DOM-09](../20-domain/dom-09-consciousness-copy.md)と[DOM-10](../20-domain/dom-10-characters.md)では、主人公はミオの診療所で、ミオが手に入れた体で目覚めると決めている。体ごとの違いがあれば、新しい体になること自体を周の楽しみにできる。

issueでは、体の種類と効果、示す数と選び方、どのノードに書くかの3つを決めることにしていた。

## 決定

1. 体の種類は、汎用の体・作業用の体・戦闘用の体・試作の体の4つにする。値は`game/data/bodies.json`に置き、MODで足せる。
2. 体の種類は、基本の劣化と効果を持つ。基本の劣化は、劣化の式の「基本の劣化」をその体の値に置き換える。効果は、インプラントや永続強化と同じ効果の種類（稼ぎ・経験・劣化・開始レベル）を使い、合計に足す。
3. 転生の画面には、毎回すべての体の種類を並んだ順に出す。乱数では選ばない。
4. 体の種類ごとに「（体の種類）で目覚める」ボタンを置き、選ぶことと転生を1回の操作にする。ボタンは横に4つ並べる。
5. 第1周は、並んだ順で最初の体の種類（汎用の体）で目覚める。#36より前のセーブの周と記録は、汎用の体だったものとして読む。
6. 記録に体の種類を残し、クロニクルの記録の数値の行の先頭に出す。体の画面の欄にも、いまの体の種類を出す。
7. 体の種類は、新しいドメインノード[DOM-11](../20-domain/dom-11-body-types.md)に書く。

## 理由

効果は[DOM-03](../20-domain/dom-03-jobs-and-skills.md)が決めているので、体の種類を[DOM-02](../20-domain/dom-02-life-and-body.md)の属性にすると、DOM-02がDOM-03に依存することになり、DOM-03からDOM-02への依存と循環する。そのため、新しいノードに分けた。

基本の劣化を効果の合計とは別に持たせたのは、劣化の効果には下限（0.2）があるからである。永続強化「頑丈な義体」とインプラント「強化骨格」を買い進めると、劣化の効果の合計は下限に届く。体の違いを劣化の効果で書くと、下限に届いたあとは劣化を下げる体の利点が消え、劣化を上げる体の不利だけが大きく残る。自動で遊ぶ検査（`playthrough.gd`）で比べたところ、劣化の効果で書いた体は、どれも汎用の体より遅かった。

体ごとの釣り合いは、エンディングまでの時間をそろえることではなく、遊び方ごとに得をする体があることを目安にした。作業用の体は1つの周が長いので、閉じている間に進めたいときや、転生の回数を減らしたいときに向く。試作の体と戦闘用の体は、周が短くなる代わりに、経験か稼ぎが大きく増える。自動で遊ぶ検査では、汎用の体だけで遊ぶとエンディングまで約40分、試作の体を選び続けると約33分だった。

すべての体の種類を毎回出すのは、種類が4つしかなく、乱数で隠すと選ぶ理由が運になるからである。イベントの結果に乱数を使わない決定（[ADR-0004](./adr-0004-event-rules.md)）とも合う。

選ぶことと目覚めることを1回の操作にしたのは、転生の画面がすでに1280×720の高さいっぱいで、選ぶ欄と目覚めるボタンを別に置く高さが無いからである。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| 体の種類をDOM-02の体の属性にする | 効果を持つので、DOM-02がDOM-03に依存し、循環する |
| 体の違いを劣化の効果だけで書く | 劣化の効果が下限に届いたあと、劣化を下げる体の利点が消える |
| 毎周、乱数で2つか3つの体を示す | 種類が4つでは隠す意味が薄く、選ぶ理由が運になる |
| 体ごとに得意なスキルの開始レベルを上げる | スキルごとの効果の種類が無く、効果の仕組みを広げる必要がある。今回は既存の効果の種類で足りる |
| 耐久の上限を体ごとに変える | 耐久を0〜100とするDOM-02の決まりと、イベントの耐久の増減の見え方が変わる。基本の劣化で、体のもちの違いは表せる |
| 選ぶ欄と目覚めるボタンを分ける | 転生の画面の高さが足りない |

## 影響

DOM-11を足し、体の種類の値を`game/data/bodies.json`に置く。言語ファイルに、体の種類ごとの`body.<id>.name`と`body.<id>.desc`を足す。DOM-03の劣化の式の「基本の劣化」は、体の種類から取る。

転生の画面の「新しい体で目覚める」ボタンは、体の種類ごとのボタンに置き換わる。転生の画面のパネルは、ボタンを横に4つ並べるために広くなる。`playthrough.gd`は、説明に書いてある効果を見て、経験がいちばん増える体を選ぶ。

体の種類を足すMODは、`bodies`に項目を足し、`body.<id>.name`と`body.<id>.desc`を言語ファイルに置く。

## 見直しの条件

体の種類を5つより多くしたくなったら、転生の画面に並べきれないので、示す数と選び方を決め直す。スキルごとの効果の種類が別の理由で入ったら、体の種類にも使うかを見直す。
