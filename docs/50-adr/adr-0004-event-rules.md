# イベントの起き方と結果を決まった量で表す

- 日付: 2026-10-18
- 状態: stable

## 背景

仕事を選んだあとは待つだけで、周ごとの違いが数値にしか出なかった。企画メモでは「企業の追跡」「仲間の裏切り」のようなイベントを考えていた（issue #5）。

決める必要があったのは、イベントの起き方、選択肢の結果の表し方、待っている間の時間の扱い、MODでイベントを足せるようにするかの4つである。

## 決定

1. イベントは仕事に就いている間だけ起きる。1秒あたりの確率は、危険度÷90とする。イベントごとに起きる仕事を決め、いまの仕事で起きるものから同じ確率で1つ選ぶ。
2. 選択肢の結果は、クレジット・耐久・経験を決まった量だけ増減させる。乱数で成否を決めることはしない。クレジットの量は、いまの稼ぎの何秒分かで書く。
3. 選択肢には、就く条件と同じ形で、選ぶ条件（スキルのレベル）を付けられる。どのイベントにも、選ぶ条件の無い選択肢を1つ以上置く。
4. 選ぶまでの間も、時間は進める。設定で「イベントで止める」を選んだときだけ、待っている間は時間を止める。設定は`user://settings.json`に、言語と一緒に置く。
5. イベントの数値は`game/data/events.json`に置き、仕事と同じくidで上書き・追加できるようにする。表示文は`game/lang/`のキー`event.<id>.name`・`event.<id>.desc`・`event.<id>.<選択肢>.name`・`event.<id>.<選択肢>.result`に置く。
6. 最初に入れるイベントは、仕事ごとに2つの計6つとする。物語文やクロニクルへの記録は入れず（issue #6）、選んだ結果をログに1行残す。

## 理由

確率を危険度に比例させると、危険な仕事ほど出来事が多くなり、稼ぎと劣化の釣り合いと同じ向きになる。平均90秒に1回なら、運び屋で1周に3回前後、傭兵ではおよそ2倍になる。

結果を決まった量にすると、選ぶ前に結果を読める。成否に乱数を使わない代わりに、選ぶ条件で腕前を反映させる。クレジットを秒数で書くのは、周を重ねて稼ぎが伸びても、イベントの重みが変わらないようにするためである。

時間を止めないのは、放置して進めるゲームだからである。止めると、放置している間にイベントが1つ起きただけで進行が止まる。一方で、じっくり選びたいプレイヤーのために、止める設定を置く。

イベントを`data/`に置くのは、既にある読み込み（`GameData`）とMODの上書きをそのまま使えるからである。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| 選択肢の成否を、スキルのレベルに応じた乱数で決める | 選ぶ前に結果が読めず、同じ選択でも結果が変わる。選ぶ条件で腕前を反映できる |
| クレジットの増減を、決まった額で書く | 周を重ねて稼ぎが伸びると、イベントの重みが小さくなっていく |
| イベントが起きたら、いつも時間を止める | 放置している間に進行が止まる |
| イベントの起きる間隔を一定にする | 起きる時刻が読めてしまい、出来事らしさが無くなる |
| イベントを本体にだけ置き、MODでは足せないようにする | 既にある読み込みを使えば、手間がほとんど増えない |

## 影響

[DOM-06](../20-domain/dom-06-events.md)ができる。[ARCH-01](../10-architecture/arch-01-game-overview.md)では、`data`の持つものにイベントが加わり、`loc.gd`が言語のほかに設定の保存も受け持つ。

経験の量は決まった値なので、スキルのレベルが上がるほど、イベントで得る経験の重みは小さくなる。

## 見直しの条件

イベントが1周に起きる回数を、プレイヤーが多すぎる、または少なすぎると感じたら、90秒を見直す。イベントで得る経験が、周を重ねると意味を持たなくなったら、経験の量の書き方を見直す。
