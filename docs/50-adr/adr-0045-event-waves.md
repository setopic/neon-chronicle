# イベントの起きやすさに、緊張と耐久で波を付ける

- 日付: 2026-10-20
- 状態: stable

## 背景

イベントは、危険度÷90の確率で起きていた（[ADR-0004](./adr-0004-event-rules.md)）。周の中で強弱が無く、危ないイベントが続いても、次も同じ確率で危ないイベントが起きた（issue #92）。

issueでは、波の作り方と、起き方の確率をどう変えるか（閉じていた時間の進行と同じ結果になるか）の2つを決めることにしていた。作者からは、推奨の案で進めてよいと言われている。

## 決定

ADR-0004の6つの決定のうち、1つめだけを改める。

1. イベントは仕事に就いている間だけ起き、1秒あたりの確率は危険度÷90とする。いまの仕事で起きるものから同じ確率で1つ選ぶ（改める。危険度÷90は基本の確率とし、下記の倍率を掛ける。ひと息つける間は穏やかなイベントから選ぶ）
2. 選択肢の結果は決まった量で、乱数で成否を決めない（そのまま）
3. 選ぶ条件を付けられ、どのイベントにも選ぶ条件の無い選択肢を置く（そのまま）
4. 選ぶまでの間も時間を進め、「イベントで止める」の設定は`user://settings.json`に置く（そのまま）
5. イベントの数値は`game/data/events.json`、表示文は`game/lang/`に置く（そのまま）
6. 最初に入れるイベントは仕事ごとに2つとし、結果をログに残す（そのまま）

新しく決めることは次のとおりである。

1. 周ごとに緊張を持つ。耐久を減らす選択肢を選ぶと、減った耐久の分だけ上がり、仕事に就いている間は1秒に0.1ずつ下がる。
2. 緊張が15以上の間を、ひと息つける間とする。その間は、イベントの起きやすさを半分にし、耐久を減らす選択肢の無い穏やかなイベントから選ぶ。
3. 耐久が0に近づくほど、イベントを起きやすくする。倍率は`1 + 0.5 × (1 - 耐久 ÷ 100)`で、耐久0の手前で1.5倍になる。
4. 新しい乱数は足さない。起きるかどうかは、これまでと同じ1回の乱数で決め、その確率に倍率を掛ける。
5. 起きやすさは、時間を進める同じ刻みの中で決めるので、閉じていた時間を進めるときも同じ式になる（[ADR-0007](./adr-0007-away-progress.md)）。
6. ひと息つける間になったらログに出し、その間は体の状態の欄に出す。
7. イベントの波は、新しいドメインノード[DOM-28](../20-domain/dom-28-event-waves.md)に書く。

## 理由

緊張を耐久の減りで上げるのは、危ない目に遭ったことが、耐久の減りでいちばんはっきり表れるからである。穏やかなイベントを、耐久を減らす選択肢の無いイベントとしたのは、データに新しい値を足さずに見分けられるからである。

耐久が0に近づくほど起きやすくしたのは、周の終わりに近いほど大きな出来事が来るようにするためである。耐久が減ったあとにイベントが増えると、倒れる前に選ぶ場面が増える。

乱数を足さなかったのは、結果を決まった量にした線（ADR-0004）を残し、起きるかどうかの乱数だけを使い続けるためである。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| イベントを、決まった順に並べた筋書きどおりに起こす | 仕事を変えたときにどの段から続けるかを決めることになる |
| 緊張を、起きたイベントの数で上げる | 穏やかなイベントが続いても緊張が上がる |
| ひと息つける間は、イベントを起こさない | 仕事の間に何も起きない時間が長くなる |
| イベントごとに強さの値を持たせる | 既存のイベントすべてに値を足すことになる |
| 周の経過時間で起きやすくする | 体の種類と体の質で寿命が変わるので、同じ時間でも周の終わりへの近さが違う |

## 影響

DOM-28を新しく起こし、緊張・ひと息つける間・穏やかなイベント・起きやすさの倍率を定義する。DOM-06の確率を基本の確率と呼び直す。ADR-0004を指していた文書は、このADRを指す。

`game_state.gd`は、周の緊張をセーブに書き、イベントの起きやすさと選び方に倍率と穏やかなイベントを使う。前の版のセーブは、緊張0として読む。体の状態の欄に、ひと息つける間を出す。

## 見直しの条件

ひと息つける間が長すぎて、イベントがほとんど起きないという声が出たら、緊張の下がり方か15の境を決め直す。1つの周に起きるイベントの数が、いまより大きく変わったら、倍率を決め直す。
