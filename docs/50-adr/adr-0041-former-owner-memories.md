# 体の元の持ち主の記憶を、体ごとの2段の話にする

- 日付: 2026-10-20
- 状態: stable

## 背景

主人公が借りている体の元の持ち主（[ADR-0040](./adr-0040-body-former-owners.md)）は、転生の画面に1行で出るだけで、話にも資料にも出ていなかった（issue #88）。その人の一生（[DOM-19](../20-domain/dom-19-resident-life-course.md)）は、遊びの中で分からなかった。

issueでは、元の持ち主を体の種類ごとに決めるか周ごとに変えるか、話の出し方の2つを決めることにしていた。作者からは、推奨の案で進めてよいと言われている。

## 決定

1. 元の持ち主は、ADR-0040のとおり体の種類ごとに1人とし、特性と同じ人にする。
2. 元の持ち主ごとに、記憶が浮かぶ2段の話を置く。1段目は暮らしの記憶、2段目は最期の記憶である。
3. 話は勢力の話のイベント（[ADR-0038](./adr-0038-stall-street-feud.md)）と同じ仕組みで、1つの周に1段ずつ進む。イベントに「体の種類」の属性を足し、その体で目覚めた周にだけ起きるようにする。
4. 起きる仕事は、運び屋・ハッカー・傭兵のどれでもよい。
5. 選択肢は、記憶を受け入れるか振り払うかの2つにする。受け入れると、元の持ち主のスキルの経験が入る。
6. 2段目で選択肢を選ぶと、新しい資料「体の元の持ち主たち」に、その人の追記が加わる。資料は最初から読める。
7. 元の持ち主の最期は、どれも下層街の死に方（[DOM-19](../20-domain/dom-19-resident-life-course.md)）に合わせる。試作の体の元の持ち主は、借金を消す契約書への署名を断ったハッカーとし、主人公と対にする。

## 理由

体の種類ごとに1人にしたのは、同じ体で周を重ねるほど、その人の話が進むようにするためである。周ごとに変えると、同じ人の話が2段目まで進まない。

2段にしたのは、体の種類が4つあり、どの体でも話を最後まで見られるようにするためである。3段にすると、体ごとに3周が要り、ほかの体を選ぶ理由が減る。

勢力の話のイベントの仕組みを使ったのは、1周に1段ずつ進む話の形がすでにあるからである。体の種類の条件を足すだけで済む。

最初から資料を読めるようにしたのは、元の持ち主がいることは転生の画面で分かっているからである。追記は、話が進んでから加わる。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| 元の持ち主を周ごとに変える | 同じ人の話が2段目まで進まない |
| 話を3段にする | 体ごとに3周が要り、ほかの体を選ぶ理由が減る |
| 話を、記憶の断片と同じく、体のスキルのレベルで戻す | 断片はエンディングまでの道のりを決めていて、数を増やすと釣り合いを決め直すことになる |
| 元の持ち主ごとに資料を分ける | 1人ずつの資料は短く、読む画面の項目だけが増える |
| 話を人物のイベントにする | 元の持ち主は登場人物ではない |

## 影響

DOM-25に、元の持ち主の話とイベントの「体の種類」の属性を足す。DOM-14の資料の一覧に「体の元の持ち主たち」を足す。

`game/data/events.json`に8つのイベントを、`game/data/profiles.json`に資料を足す。`game_state.gd`は、体の種類を持つイベントを、その体で目覚めた周にだけ起こす。セーブの形は変えない。

## 見直しの条件

体の種類を足したら、その元の持ち主の話も足す。元の持ち主の話を最後まで見た人が多くなり、続きを求める声が出たら、3段目を足すかを決める。
