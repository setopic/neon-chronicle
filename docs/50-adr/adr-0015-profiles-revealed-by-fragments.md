# 街と人物の資料を上のボタンから開き、記憶の断片が戻るまで追記を伏せる

- 日付: 2026-10-18
- 状態: stable

## 背景

ミオやジンがどんな人物か、ネオン・シティと主人公がどういう状況にあるかは、ログの1行・ミオの一言・記憶の断片・ジンの依頼の台詞に少しずつ出るだけで、まとめて読める場所が無かった（issue #42）。設定は[DOM-01](../20-domain/dom-01-world.md)・[DOM-09](../20-domain/dom-09-consciousness-copy.md)・[DOM-10](../20-domain/dom-10-characters.md)にあるが、プレイヤーには見えない。

issueでは、どこから開くか、何を載せるか、記憶の断片やエンディングで明かすことをいつから載せるかの3つを決めることにしていた。

## 決定

1. 上のボタンに「街と人物」を足し、押すと資料を並べた画面を開く。「記憶」の画面とは分ける。
2. 資料は、ネオン・シティ・自分（主人公）・ミオ・ジン・レイの5つにする。九条は、まだ名前で画面に出ないので載せない。
3. 最初は、遊んでいればすでに分かることだけを資料に書く。記憶の断片で明かすことは、その断片が戻ってから追記として加える。
4. レイの資料は、レイの1段目のイベントで選択肢を選ぶまで出さない。人物のイベントで分かることも、そのイベントのあとに追記として加える。
5. エンディングで明かすことは載せない。エンディングを見たあとの資料は、すべての断片が戻ったときと同じである。
6. 資料と追記は`game/data/profiles.json`に置き、文は言語ファイルの`profile.<id>.name`・`profile.<id>.desc`・`profile.<id>.<追記>`に置く。MODで足せる。

## 理由

「記憶」の画面と分けたのは、「記憶」が主人公の失った過去を戻った順に読む画面だからである。街や人物の説明を混ぜると、断片の文と資料の文が同じことを2度言う並びになる。

追記を断片の後ろに置いたのは、断片が明かすことを先に読めないようにするためである。断片はミオが技師だったこと、ジンが昔の仲間だったことを明かす場面として書いてあり（[ADR-0009](./adr-0009-world-rationale-and-characters.md)）、資料に最初から書くとその場面の意味が無くなる。追記にすると、断片が戻るたびに資料が書き足され、読み返す理由にもなる。

エンディングの追記を置かなかったのは、エンディングの後の物語が、エンディングの文に書いた分しか決まっていないからである。資料のために新しく書けば、エンディングの文に無いことを足すことになる。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| 「記憶」の画面に資料を足す | 断片の文と資料の文が同じことを2度言う。画面の役目も、失った記憶を読むことから外れる |
| 最初からすべてを載せる | 記憶の断片が明かすことを、断片が戻る前に読めてしまう |
| 断片が戻ってから資料そのものを出す | ミオとジンは最初の周から出てくるので、最初の周に読める資料が無くなる |
| 九条の資料も置く | 九条は、まだ名前で画面に出ない。資料だけで初めて名前を知ることになる |
| エンディングのあとに追記を足す | エンディングの文に無い後日談を、新しく書くことになる |

## 影響

DOM-14を足し、資料の値を`game/data/profiles.json`に置く。言語ファイルに、資料と追記の文を足す。

上のボタンが1つ増える。資料の画面は、記憶やライセンスの画面と同じく、閉じるまでほかの操作を受けない。

`check_data.py`は、資料と追記の文のキーがあることと、要る断片と出るイベントがdataにあることを確かめる。

## 見直しの条件

上のボタンが画面の幅に入らなくなったら、「記憶」と「街と人物」を1つの画面のタブにまとめることを考える。九条が名前で画面に出るようになったら、九条の資料を足す。
