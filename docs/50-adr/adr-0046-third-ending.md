# レイとの約束と屋台組合の評判で開く、3つ目のエンディングを足す

- 日付: 2026-10-20
- 状態: stable

## 背景

エンディングは「本当の体」と「ネットの亡霊」の2つだった（[ADR-0006](./adr-0006-fragments-and-endings.md)）。どちらも最後の仕事のイベントで選ぶだけで、それまでの周で何をしてきたかは、エンディングに表れなかった（issue #93）。ADR-0006は、エンディングを3つ以上にしたくなったら見直すとしていた。

issueでは、3つ目の結末の中身と、開く条件の2つを決めることにしていた。作者からは、推奨の案で進めてよいと言われている。

## 決定

ADR-0006の5つの決定のうち、2つめだけを改める。

1. 記憶の断片を5つ置き、スキルのレベルの条件で決まった順に戻す（そのまま）
2. 断片がすべて戻ると最後の仕事に就け、イベント「中枢の扉」にエンディングの選択肢を2つ置く（改める。下記の1）
3. エンディングの選択肢を選ぶと周が終わり、エンディングを見たあとも遊び続けられる（そのまま）
4. 最初から最後まで約1時間で遊べるように断片の条件を決め、自動で遊ぶ検査をCIで回す（そのまま）
5. 断片とエンディングは`game/data/story.json`に置く（そのまま）

新しく決めることは次のとおりである。

1. 「中枢の扉」に、3つ目のエンディングの選択肢「眠る被験体たちを目覚めさせる」を足す。エンディングは「目覚めの日」とする。
2. 目覚めの日では、レイと一緒に、中枢サーバーの奥で眠らされている被験体の体を、自分の体と一緒にすべて目覚めさせる。目覚めた人々は、屋台組合が下層街の奥に迎え入れる。
3. 開く条件は2つにする。レイの3段目で「一緒に行くと約束する」を選んでいることと、屋台組合の評判が5に届いていることである。
4. レイとの約束は、選択肢の「話の条件」で見る。満たさないあいだは選択肢を出さない。評判の条件は、満たさないあいだも選択肢を出し、選べない状態にして条件を添える。
5. 目覚めの日は、新しいドメインノード[DOM-29](../20-domain/dom-29-day-of-waking.md)に書く。

## 理由

レイとの約束を条件にしたのは、ネットの亡霊でレイを含む被験体を解き放つという結末（DOM-10）と、同じ方向で別の終わり方にするためである。ネットの亡霊は主人公が体を捨てて解き放つが、目覚めの日は全員が体に戻る。

屋台組合の評判を条件にしたのは、目覚めた人々の行き場を、下層街で住む場所を割り振る屋台組合（[ADR-0026](./adr-0026-union-ledger-and-housing.md)）が受け持つからである。屋台組合の側に立ってきた周回の積み重ねが、エンディングに表れる。

レイとの約束を満たさないあいだは選択肢を出さないのは、目覚めの日があることを、レイの話を進める前に明かさないためである。評判の条件は、選択肢を見てから評判を上げに戻れるように出しておく。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| 目覚めの日を、レイとの約束だけで開く | それまでの周の評判がエンディングに表れない |
| 目覚めの日を、ミオの話の結末で開く | ミオの話は主人公の目覚める場所を守る話で、被験体を目覚めさせる話とつながらない |
| 3つ目のエンディングで、ザンダー・ファミリーの側に立つ結末にする | 被験体の借金を買い取ったのはヨミ・システムズの研究部門で、ファミリーには被験体を目覚めさせる理由が無い |
| 条件を満たさないあいだも、選択肢を選べない状態で出す | レイの話を進める前に、結末があることを明かしてしまう |
| 前の選択の条件を、ほかの人物の段にも使えるように広げる | 前の選択の条件の検査（同じ人物の前の段を指すか）が働かなくなる |

## 影響

DOM-29を新しく起こし、目覚めの日と話の条件を定義する。DOM-08のエンディングの数と用語を3つに改める。ADR-0006を指していた文書は、このADRを指す。

`game/data/events.json`の「中枢の扉」に選択肢を、`game/data/story.json`にエンディングを足す。`game_state.gd`は、話の条件を満たさない選択肢を出さない。`check_data.py`は、話の条件がある選択肢を指しているかを確かめる。`playthrough.gd`は、これまでどおり本当の体を選ぶ。

## 見直しの条件

エンディングを4つ以上にしたくなったら、「中枢の扉」の選択肢の並べ方と、開く条件の出し方を決め直す。
