# 体の種類ごとに元の持ち主を1人決め、その特性を持たせる

- 日付: 2026-10-20
- 状態: deprecated（[ADR-0061](./adr-0061-nerve-pattern-of-former-owners.md)が置き換えた）

## 背景

体の種類を選ぶ場面は、体の質が高い体を選ぶだけになりやすかった（[ADR-0032](./adr-0032-body-quality-and-memory-software.md)）。使い捨ての体は下層街の死者から取った部品で組み立てる（[DOM-20](../20-domain/dom-20-test-subjects-origin.md)）が、その死者が誰だったかは、遊びに出ていなかった（issue #87）。

issueでは、特性の種類と効果、体への付き方（乱数か、周番号から決めるか）の2つを決めることにしていた。作者からは、推奨の案で進めてよいと言われている。

## 決定

1. 体の種類ごとに、神経と腕の部品を取った元の持ち主を1人決める。元の持ち主は周によって変わらない。
2. 特性は、元の持ち主の生き方が体に残した癖で、効果を1つ持つ。汎用の体は交渉の経験 +20%、作業用の体は稼ぎ +10%、戦闘用の体は格闘の経験 +30%、試作の体はハッキングの経験 +30%とする。
3. 特性は乱数でも周番号でも決めず、体の種類に1つずつ固定する。
4. 特性の効果は、体の種類の効果に足す。スキルごとの経験の効果は、永続強化の型と同じく、仕事で得る経験にだけ効く。
5. 転生の画面の体の種類のボタンと、体の状態の欄に、元の持ち主と特性を出す。
6. 元の持ち主と特性は、新しいドメインノード[DOM-25](../20-domain/dom-25-body-former-owners.md)に書く。

## 理由

元の持ち主を体の種類ごとに1人に固定したのは、ミオが同じ種類の体を同じ組み立て方で作るとすれば、神経と腕の出どころも同じになるからである。周ごとに変えると、元の持ち主の話（issue #88）を周をまたいで進められない。

特性を固定したのは、体を乱数で選ばない決まり（[ADR-0012](./adr-0012-choose-body-on-rebirth.md)とADR-0032）に合わせるためである。周番号で回すと、同じ体の種類でも周ごとに特性が変わり、体の種類の説明が1つに定まらない。

特性の効果をスキルごとの経験にしたのは、体の種類の効果（劣化・稼ぎ・経験の全体）と重ならず、伸ばしたいスキルで体を選ぶ理由ができるからである。汎用の体は、ほかの体が選べない周でも選ぶので、交渉の経験という小さな効果にした。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| 特性を乱数で付ける | 体を乱数で選ばない決まりに合わない |
| 特性を周番号で回す | 同じ体の種類でも周ごとに特性が変わり、元の持ち主の話を進められない |
| 特性で、イベントの選択肢を選べなくする | 選べない選択肢が増えると、縛りや評判の条件と重なって分かりにくい |
| 部品ごとに別の元の持ち主を持たせる | 1つの体に何人もの話が混ざる |
| 特性の効果を、体の種類の効果に書き足す | 体の種類の効果と特性の区別が、画面でも文書でも付かなくなる |

## 影響

DOM-25を新しく起こし、元の持ち主と特性を定義する。

`game/data/bodies.json`の体の種類に`trait_effects`を足す。`game_state.gd`は、効果の合計に特性の効果を足す。転生の画面と体の状態の欄に、元の持ち主と特性を出す。セーブの形は変えない。

## 見直しの条件

特性のせいで、いつも同じ体の種類が選ばれるようになったら、効果を決め直す。体の種類を足したら、その元の持ち主と特性も決める。
