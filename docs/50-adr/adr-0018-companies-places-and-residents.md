# 街を複数の企業が分け合い、場所と住人をイベントと資料に出す

- 日付: 2026-10-18
- 状態: stable

## 背景

ネオン・シティの様子は、仕事とイベントの短い文と、「街と人物」の資料にしか出なかった。街の場所や勢力、仕事の現場の様子、企業以外の人々は、ほとんど書いていなかった（issue #47）。

[DOM-01](../20-domain/dom-01-world.md)の「企業」は、街を支配する1社を指していた。1社しかないと、企業同士の経済や製品の競争が書けない。プレイヤーとの話し合いで、企業を複数にすることにした。

issueでは、どこに細部を足すかと、新しく決める設定の範囲の2つを決めることにしていた。

## 決定

1. ネオン・シティは、数社の巨大企業が分け合って支配する。主人公の意識をデータにした企業をヨミ・システムズと名付け、DOM-01に置く。
2. ゲームの文のうち、反復計画・中枢サーバー・契約書・エンディングのように主人公の話に関わるものは、「企業」をヨミ・システムズに直す。「企業の私兵」「企業のネット」「企業の汚れ仕事」のように、どの企業にも当てはまる文はそのまま残す。
3. ヨミ・システムズ以外の企業（ヴァルデック義体・モンフォール警備）と、場所（下層街・闇市場・企業区画）、企業に属さない人々（下層街の住人・路地のチンピラ）を、[DOM-15](../20-domain/dom-15-city-places-and-powers.md)に置く。どれも文だけで、数値は持たない。社名は、ヨミ・システムズだけをアジア系にし、ほかの企業はヨーロッパ系にする。
4. 3つの仕事の説明に、仕事の場所を書き足す。
5. 仕事ごとに1つずつ、企業同士の争いと下層街の住人が出るイベントを足す（「薬の配達」「闇市場の買い手」「変電所の奪い合い」）。イベントの仕組みは変えない。
6. 「街と人物」に、企業・企業区画・下層街・闇市場の4つの資料を足す。どれも最初から読める。
7. ヨミ・システムズが主人公の意識をデータにしたことは、記憶の断片「契約書」が戻るまで画面に出さない。それまでは、ヨミ・システムズは街の企業の1社として出る。

## 理由

主人公の話に関わる文だけを社名に直したのは、それ以外の文は企業が複数でもそのまま読めるからである。すべてを社名に直すと、どの社の話かを1つずつ新しく決めることになり、設定が増えすぎる。

細部を新しい仕組みではなくイベントと資料の文で足したのは、マイルストーンの残りがこのissueだけで、仕組みを足すと遊び通しての確認が増えるからである。イベントの文は仕事中に必ず目に入り、資料はいつでも読める。

企業に属さない人々を、名前のある人物ではなく下層街の住人として書いたのは、[DOM-10](../20-domain/dom-10-characters.md)の4人と役が重ならないようにするためである。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| 企業を1社のままにする | 企業同士の経済や製品の競争が書けない |
| 1社の支配のまま、小さな競合会社を足す | 競合が支配する側に並ばないので、仕事やイベントで企業同士の争いを書きにくい |
| ゲームの「企業」をすべて社名に直す | 社ごとに新しく決めることが増え、どの社かに意味の無い文まで書き換えることになる |
| 企業ごとの評判や関係の値を持たせる | 新しい数値と画面が要り、遊び通しての確認が増える |
| 仕事中のログに場所の文を流す | ログの欄が埋まり、イベントや技能の上昇の行が流れて読めなくなる |
| 住人に名前のある人物を足す | DOM-10の人物と役が重なり、人物のイベントの設計まで要る |

## 影響

DOM-01の用語「企業」の意味を、街を分け合う巨大企業の1社に変え、用語「ヨミ・システムズ」を足す。[DOM-08](../20-domain/dom-08-memory-fragments-and-endings.md)・[DOM-09](../20-domain/dom-09-consciousness-copy.md)・[DOM-10](../20-domain/dom-10-characters.md)で、主人公の話に関わる「企業」をヨミ・システムズに直す。仕組みは変わらない。

`game/data/events.json`に3つのイベントを、`game/data/profiles.json`に4つの資料を足す。言語ファイルでは、記憶の断片・エンディング・最後の仕事・資料の文の社名を直し、新しいイベントと資料のキーを足す。

## 見直しの条件

企業ごとの仕事や評判を、数値として扱いたくなったら見直す。
