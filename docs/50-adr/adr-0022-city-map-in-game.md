# 街の地図を「街と人物」の画面にタブで出し、中枢サーバーは断片が戻るまで伏せる

- 日付: 2026-10-19
- 状態: deprecated（[ADR-0023](./adr-0023-bridge-names-and-terrain-map.md)が置き換えた）

## 背景

[ADR-0020](./adr-0020-city-districts-and-map.md)は、街を区画と3本の橋で分け、地図を[DOM-15](../20-domain/dom-15-city-places-and-powers.md)の図として残した。ゲームの画面には地図を出さず、出すかどうかは別のissueで決めることにしていた（issue #56）。

issueでは、地図をどの画面に出すか、どう描くか、最初から全部見せるかの3つを決めることにしていた。

## 決定

ADR-0020の6つの決定のうち、6つめだけを改める。

1. 区画を1段だけ足し、企業区画を4つの縄張りに、下層街を3つの区画に分ける（そのまま）
2. 企業区画は高台、下層街は低い土地にあり、3本の橋でつながる（そのまま）
3. 3本の橋の位置（そのまま）
4. 闇市場の入口と裏通りの診療所の位置（そのまま）
5. 変電所・ジンが忠告する橋・中枢サーバーの位置と、ジンに居場所を置かないこと（そのまま）
6. 地図をDOM-15に図として載せる（そのまま）。ゲームの画面に地図を出す（改める。下記）

地図は「街と人物」の画面に置き、資料とタブで切り替える。上のボタンは増やさない。

地図は、Godotで箱と線を描いて作る。画像は用意しない。区画・橋・つながりはDOM-15の図と同じ配置にし、名前と添える文は言語ファイルに書く。

区画と橋は、最初からすべて見せる。中枢サーバーだけは、記憶の断片「中枢サーバー」が戻るまで描かない。

## 理由

「街と人物」の画面に置いたのは、地図が資料と同じく街を説明するもので、読むだけでゲームの状態を変えないからである。上のボタンの2段目は、英語では1280の幅にほとんど余りが無い（[ADR-0017](./adr-0017-header-and-dialog-look.md)）。

箱と線で描いたのは、言語を切り替えたときに、名前を言語ファイルから引いてそのまま描き直せるからである。画像にすると、言語ごとに絵を用意することになり、外部の素材を使えばライセンスの表記も要る。DOM-15の図も箱と線なので、そのまま写せる。

区画と橋を最初から見せるのは、どれも最初の周から資料やイベントの文に出てくる場所だからである。中枢サーバーは、資料のネオン・シティの追記と同じく、記憶の断片「中枢サーバー」が戻ってから明かす（[DOM-14](../20-domain/dom-14-city-and-people-profiles.md)）。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| 上に「地図」のボタンを足す | 英語では、上のボタンの2段目が1280の幅に収まらなくなる |
| 画像を用意する | 言語ごとに絵が要る。外部の素材を使うとライセンスの表記も要る |
| 区画も、行ったことのある仕事やイベントに合わせて明かす | 区画はどれも最初から文に出てくるので、伏せる理由が無い。明かす条件を決めて保存するための作業が増える |
| 今いる場所を地図に示す | 仕事やイベントに場所を持たせていないので、示す場所が決まらない |

## 影響

DOM-16を足し、地図の描くものと出る条件を書く。DOM-14の資料は変えない。「街と人物」の画面は、資料と地図のタブに分かれる。言語ファイルに、地図の名前と添える文のキー（`map.*`）と、タブの名前のキーを足す。

## 見直しの条件

仕事やイベントに場所を持たせると決めたら、今いる場所を地図に示すかを見直す。DOM-15に区画や橋が増えたときは、地図の配置が収まるかを見直す。
