# 1つ前の周の選択を、次の周の跡のイベントに出す

- 日付: 2026-10-20
- 状態: deprecated（[ADR-0063](./adr-0063-recognizing-across-lives.md)が置き換えた）

## 背景

転生すると、前の周の選択は記録の物語文に残るだけで、街は何も覚えていなかった（[DOM-07](../20-domain/dom-07-chronicle-story.md)、issue #91）。体が替わっても主人公は同じ人なのに、前の周に助けた人や裏切った相手が、次の周に何も言ってこなかった。

issueでは、残す選択の記録と何周前まで効かせるか、出し方（イベントの説明文か選べる選択肢か）の2つを決めることにしていた。作者からは、推奨の案で進めてよいと言われている。

## 決定

1. 周ごとに、その周に選んだ選択肢をイベントのidごとに残す。周が終わると、それを1つ前の周の選択として持ち、転生しても残す。
2. 効くのは1つ前の周だけにする。
3. 出し方は、新しい跡のイベントにする。跡のイベントは、1つ前の周に決まった選択肢を選んだときだけ起きる。説明文の書き分けや、既存のイベントへの選択肢の追加はしない。
4. 跡のイベントを4つ置く。薬の配達で薬を届けた、偽の身元で作り直した、盗電の線で線の場所を売った、保護料の運びで袋を持って逃げた、の4つの次の周に起きる。
5. 跡のイベントでは、街の人々が、顔は違っても歩き方や作業用の名前で主人公だと気づく。
6. 前の版のセーブには周ごとの選択が無いので、読み込んだ周が終わったあとの周から、跡のイベントが起きうる。
7. 前の周の跡は、新しいドメインノード[DOM-27](../20-domain/dom-27-traces-of-last-life.md)に書く。

## 理由

1つ前の周だけにしたのは、1周は数分で終わり、2周前のことまで覚えている人は少ないからである。何周も前まで効かせると、どの周の選択が効いたのかが分かりにくい。

新しいイベントにしたのは、既存のイベントの文と選択肢を変えずに済み、跡の起きたことがはっきり分かるからである。説明文の書き分けは人物のイベントの段どうしの仕組みで、ふつうのイベントには使っていない。

記録には選択肢のidだけを残し、文は残さない。記録に文を残さない決まり（[ADR-0005](./adr-0005-chronicle-story.md)）に合わせるためである。

顔ではなく歩き方や作業用の名前で気づかせるのは、体が毎周替わるという設定（[DOM-09](../20-domain/dom-09-consciousness-copy.md)）と食い違わないようにするためである。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| すべての周の選択を残し、何周前でも効かせる | どの周の選択が効いたのかが分かりにくい |
| 既存のイベントの説明文を、前の周の選択で書き分ける | 既存の文を書き直すことになり、書き分けの仕組みもふつうのイベントには使っていない |
| 既存のイベントに、前の周の選択で開く選択肢を足す | 選択肢が増えすぎて、評判の条件の選択肢と見分けにくい |
| 記録の物語文を、次の周のイベントに引く | 記録には文を残さない |

## 影響

DOM-27を新しく起こし、前の周の跡・跡のイベント・跡の条件を定義する。

`game/data/events.json`に跡のイベントを4つ足す。`game_state.gd`は、その周の選択と1つ前の周の選択をセーブに書き、跡の条件を見てイベントを起こす。`check_data.py`は、跡の条件がある選択肢を指しているかを確かめる。

## 見直しの条件

跡のイベントが少なく、前の周の行いが街に残っていると感じにくいという声が出たら、跡のイベントを足す。2つ前の周まで効かせたくなったら、残す周の数を決め直す。
