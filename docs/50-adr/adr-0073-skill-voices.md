# スキルを、主人公の頭の中の声としてイベントで話させる

- 日付: 2026-10-20
- 状態: stable


## 背景

Robert Kurvitzは『Disco Elysium』で、主人公の技能を頭の中の声として書き、声どうしが言い争ったり失敗をからかったりするようにしたと語っている（issue #143、二次の情報）。

本作のスキル（ハッキング・格闘・交渉）は、数値として効くだけで、話の中で声を持たなかった（[DOM-03](../20-domain/dom-03-jobs-and-skills.md)）。41のイベントのうち、スキルの選ぶ条件を持つ選択肢は17あり、内訳はハッキング8・交渉7・格闘2である。条件を満たさない選択肢は、押せないボタンとして出るだけだった（[DOM-06](../20-domain/dom-06-events.md)）。

前の周を主人公に返す仕組みは、すでに2つある。街の人々が話す前の周の跡（[DOM-27](../20-domain/dom-27-traces-of-last-life.md)）と、前の周の自分が戻ってくる記憶の断片（[DOM-08](../20-domain/dom-08-memory-fragments-and-endings.md)）である。

## 決定

1. スキルに、主人公の頭の中の声を持たせる。声が話すのはイベントの画面だけで、ログには出さない。
2. スキルの選ぶ条件を持つ選択肢があるイベントでは、説明文の下に、その選択肢ごとに条件のスキルの声を1行出す。条件を満たしていれば、選択肢ごとの文で勧める（17行）。満たしていなければ、スキルごとの共通の文で、いまの腕では足りないとからかう（3行）。
3. 3つの声は、ハッキングを短く冷たく数字と手順で、格闘を荒っぽい命令形で体の感覚で、交渉を軽口で相手の弱みと値段を見て話すように書き分ける。声の主の名前は、スキルの名前をそのまま使う。
4. 声は、いまの体で積んだ腕前から見えることだけを話し、前の周の行いや記憶には触れない。前の周の跡と記憶の断片とは、この点で分ける。
5. 声は、選んだ結果の中身を先に明かさない。
6. 文は、ほかの表示文と同じく、フォントの部分集合にある文字だけで書く（[ADR-0010](./adr-0010-characters-in-screen-text.md)）。

## 理由

イベントの画面に絞ったのは、スキルの選ぶ条件が、イベントで主人公がどう動けるかを直接変える場所だからである。条件を満たさない選択肢をからかう声にすると、押せないボタンが、次にそのスキルを上げる理由として読めるようになる。からかう声をスキルごとの共通の文にしたのは、満たしていない理由はどの選択肢でも「腕が足りない」の1つで、選択肢ごとに書き分けても伝わる中身が増えないからである。

声に前の周を話させないのは、スキルが周ごとに開始レベルへ戻るからである。いまの体で上げた腕前の声が前の周を知っていると、跡と断片の役目と重なり、どれが前の周を返す仕組みなのかが分からなくなる。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| レベルが上がったときや節目に届いたときのログも、声で書く | ログの行が増えるほど、イベントの画面での声が目立たなくなる。文の数も大きく増える |
| 声どうしを言い争わせる | 2つのスキルの条件を持つイベントは1つだけで、言い争う場面がほとんど作れない |
| 声に、前の周の自分の跡を話させる | 前の周の跡と記憶の断片と役目が重なる |
| からかう声も選択肢ごとに書く | 満たしていない理由は腕が足りないことの1つで、書き分けても中身が増えない |

## 影響

[DOM-32](../20-domain/dom-32-skill-voices.md)を起こし、選択肢に勧める声を、スキルにからかう声を足す。イベントの画面では、説明文と選択肢の間に、スキルの声の行が出る。`game/ci/check_data.py`は、勧める声とからかう声の文のキーがあるかを確かめる。

## 見直しの条件

スキルの条件を持つ選択肢が大きく増えて、1つのイベントに声が3行以上並ぶようになったら、出し方を見直す。実際に遊んだ人が声を読み飛ばしているなら、出す場所を見直す。
