# 閉じていた時間を、開いたときにまとめて進める

- 日付: 2026-10-18
- 状態: stable

## 背景

放置して進めるゲームなのに、閉じているあいだは何も進まなかった（issue #9）。ブラウザ版では、タブを裏に回したあいだもフレームが来ず、戻ったときに進めるのは60秒までだった。

決める必要があったのは、何時間分まで進めるかと、閉じているあいだに耐久が0になったときの扱いの2つである。

## 決定

1. セーブに、セーブした時刻を残す。開いたときは、その時刻から今までの時間を進める。
2. タブが裏にあった時間も、閉じていた時間と同じに扱う。前のフレームから1秒より空いたら、空いた時間を壁の時計で測って進める。
3. 進めるのは8時間までとする。時計が戻っていたら進めない。
4. 進め方は、開いているときと同じ0.25秒の刻みとする。イベントも同じように起き、「イベントで止める」を選んでいれば、イベントが起きたところで時間が止まる（[ADR-0004](./adr-0004-event-rules.md)）。
5. 閉じているあいだに耐久が0になったら、開いているときと同じく周を終える。自動では転生せず、開いたときは転生の画面で待つ。
6. 60秒以上進めたときは、閉じていた時間をログに1行残す。
7. 窓がフォーカスを失ったときと閉じるときにも保存する。

## 理由

開いているときと同じ刻みで進めると、規則を2つ持たずに済み、閉じていても開いていても同じ結果になる。1つの周は劣化が最も小さくても約21分で終わり、周が終わったあとの刻みは何もしないので、8時間分を1フレームで進めても重くならない。

周を終えるのは、開いているときと規則をそろえるためである。周の終わりは記憶ポイントという前進でもあり、戻ってきたプレイヤーは転生の画面で永続強化を選べる。

8時間は、寝ているあいだの分が進む長さで、放置するゲームでよく使われる。いまの周の長さでは、上限が効くのは端末の時計が大きくずれたときくらいである。

ブラウザでは、タブを閉じる前に保存の機会が来ないことがある。5秒ごとの保存に加えて、フォーカスを失ったときにも保存しておけば、失う時間はほとんど無い。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| 耐久が0になる直前で止め、開いてから続きを遊ぶ | 閉じているときだけ規則が変わる。長く閉じても周が終わらず、記憶ポイントも得られない |
| 周が終わったら自動で転生して進め続ける | 永続強化の購入や仕事の選択が無いまま周が進む。周回の特典で解放する案として、issue #22で別に決める |
| 上限を24時間にする | いまの周の長さでは8時間と差が出ない |
| 上限を設けない | 端末の時計を進めると、何日分でも一度に進められる |
| 閉じていた時間を、平均の稼ぎで一度に計算する | イベントと耐久の扱いが開いているときと変わり、規則を2つ保守することになる |

## 影響

[DOM-02](../20-domain/dom-02-life-and-body.md)では、閉じていた時間も時間として進む。[ARCH-01](../10-architecture/arch-01-game-overview.md)では、セーブがセーブした時刻を持ち、未決事項からオフライン中の進行が外れる。CIの`game/ci/away.gd`が、セーブの時刻をずらしてロードし、閉じていた時間の分だけ進むことを確かめる。

## 見直しの条件

周が数時間続くようになって8時間の上限が効きはじめたら、上限を見直す。自動の転生を入れたら（issue #22）、決定の5を見直す。
