# ジンの依頼を2つ並べ、受けるものを選ばせる

- 日付: 2026-10-20
- 状態: stable

## 背景

ジンの依頼は、周番号で1つに決まり、断ることも選ぶこともできなかった（[ADR-0013](./adr-0013-jin-requests.md)）。上乗せはどの依頼も記憶ポイントの半分で、依頼に迷う場面が無かった（issue #81）。ADR-0013は、依頼を選びたいという声が出たら選び方を決め直すとしていた。

issueでは、2つの依頼の並べ方と差の付け方、どちらも選ばないことを認めるかの2つを決めることにしていた。作者からは、推奨の案で進めてよいと言われている。

## 決定

ADR-0013の7つの決定のうち、4つはそのまま引き継ぐ。

1. 依頼の種類は「仕事」と「スキル」の2つで、値は`game/data/requests.json`に置き、MODで足せる（そのまま）
2. 依頼は1つの周に1つだけ示し、断ることも選ぶこともできない（改める。下記の1〜3）
3. 示す依頼は乱数で選ばず、示せる依頼を周の番号で順に回す（改める。下記の1）
4. 依頼を果たした周は、記憶ポイントの半分を上乗せする（改める。下記の4）
5. 周の始まりにジンの台詞で依頼をログに出し、体の状態の欄に中身と進み具合を出す（改める。下記の5）
6. 依頼を果たしたらログに出し、転生の画面に上乗せの分を添える（そのまま）
7. 依頼はDOM-12に書く（そのまま）

新しく決めることは次のとおりである。

1. 周の始まりに、示せる依頼を2つ並べる。1つめは`示せる依頼[(周の番号 - 1) mod 示せる依頼の数]`、2つめはその次の`示せる依頼[周の番号 mod 示せる依頼の数]`とする。示せる依頼が1つしか無いときは1つだけ並べる。乱数は使わない。
2. 並べた依頼のうち1つを受ける。受けるのは周の間ならいつでもよく、受けたあとは周の終わりまで変わらない。
3. どちらも受けないことを認める。受けなくても、失うものは無い。
4. 依頼ごとに上乗せの割合を持たせる。仕事の依頼は0.4、スキルの依頼は0.7とする。割合を持たない依頼は0.5とする。上乗せは`max(1, round(周の終わりに得る記憶ポイント × 上乗せの割合))`とする。
5. 周の始まりに、並べた依頼ごとにジンの台詞をログに出す。体の状態の欄には、受けるまでは依頼ごとのボタンを出し、ボタンに中身と上乗せの割合を出す。受けたあとは、いまと同じく中身と進み具合を出す。
6. 依頼の進み具合は、受けたときからではなく、周の始まりから数える。

## 理由

2つめを周の番号で次の依頼にしたのは、乱数を使わないというADR-0013の線を残すためである。`requests.json`は仕事の依頼とスキルの依頼を交互に並べているので、隣どうしの2つは、たいてい種類が違う。

仕事の依頼は決まった時間だけ就けば果たせるので、確実だが上乗せは小さい。スキルの依頼は周の終わりまでに届かないこともあるので、上乗せを大きくした。どちらを受けるかで、その周の過ごし方が変わる。2つの割合の平均は、これまでの0.5に近い。

受けるのを周の間ならいつでもよいとし、進み具合を周の始まりから数えるのは、放置で進めているあいだに受けそこねても損をしないようにするためである（[ADR-0007](./adr-0007-away-progress.md)）。進み具合を受けたときから数えると、受けた時点の値を持つことになる。

どちらも受けないことを認めたのは、ADR-0013と同じく、果たさなくても失うものが無いからである。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| 2つの依頼を乱数で選ぶ | ADR-0013の、乱数を使わない線から外れる |
| 2つめに、示せる依頼の中でいちばん難しいものを出す | 難しさの順を決める値が要る |
| 依頼を3つ以上並べる | 体の状態の欄が長くなる。2つで選ぶ場面は作れる |
| 依頼を受けないと、記憶ポイントを減らす | 果たさなくても失うものが無い、という線を変えることになる |
| 依頼は周の始まりにしか受けられない | 放置で進めているあいだに受けそこねる |
| 進み具合を受けたときから数える | 受けた時点の値をセーブに持つことになる |

## 影響

DOM-12の定義と不変条件を、2つ並べて1つを受ける形に改める。依頼に上乗せの割合の属性を足し、周の属性に並べた依頼を足す。

`game_state.gd`は、並べた依頼をセーブに書き、受けたら依頼として持つ。前の版のセーブで依頼をすでに持っていれば、受けたものとして扱う。体の状態の欄に、依頼を受けるボタンを置く。`playthrough.gd`は、これまでどおり依頼を狙わない。

## 見直しの条件

どちらか一方の種類ばかりが受けられるようになったら、上乗せの割合を決め直す。依頼を3つ以上並べたくなったら、体の状態の欄の並べ方を決め直す。
