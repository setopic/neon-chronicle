# 生き直しを闇医者が乗っ取った企業の計画として説明し、4人の人物を置く

- 日付: 2026-10-18
- 状態: deprecated（[ADR-0064](./adr-0064-resolve-loose-threads.md)が置き換えた）

## 背景

記憶の断片「計画書」で、企業が抜き取った意識を使い捨ての体に入れ、倒れたら新しい体で目覚めさせていることは分かる。一方で、企業の計画の一部なのに、なぜ主人公が企業に逆らう仕事まで自由に選べるのかは説明していなかった。記憶ポイント・永続強化・クレジットとスキルが周ごとに戻ること・残るインプラントにも、世界の中での理由が無かった。

名前のある人物もいなかった。出てくるのは主人公と企業だけで、周を重ねても関係が深まる相手がいなかった。

## 決定

1. 生き直しを、企業の研究部門の反復計画として説明する。体が倒れると、企業の装置が意識の写しを新しい体へ読み込む（[DOM-09](../20-domain/dom-09-consciousness-copy.md)）。
2. 主人公の意識の写しだけは、闇医者のミオが読み込み先を書き換えていて、企業の施設ではなく裏通りの診療所で目覚める。これを、主人公が企業の命令を受けずに仕事を選べる理由にする。
3. 記憶ポイントは、体が倒れる瞬間の同期で送り返せた記憶の量とする。永続強化は、その記憶で次の目覚めを調整することとする。スキル・クレジット・残るインプラントの理由は、DOM-09の表のとおりにする。
4. 名前のある人物を4人置く。ミオ・ジン・レイ・九条で、それぞれを記憶の断片かエンディングに結びつける（[DOM-10](../20-domain/dom-10-characters.md)）。
5. いまある記憶の断片とエンディングの文は、この設定と食い違わない。人物の名前を画面の文に入れることは、別のissueで行う。

## 理由

企業の計画をそのまま使ったのは、記憶の断片「計画書」がすでにそう書いていて、文を書き直さずに済むからである。そのうえで読み込み先を書き換えた人を置くと、自由に仕事を選べる理由と、毎周迎えてくれる人物が一度に手に入る。

ミオを「白い部屋」の技師の1人にしたのは、記憶の断片の中に、主人公を逃がした理由を置くためである。断片を読み進めると、迎えてくれていた人物の見え方が変わる。

ジンを主人公に気づかない昔の仲間にしたのは、体が毎周新しくなることを、仕組みではなく人間関係として感じさせるためである。レイを同じ被験体にしたのは、エンディング「ネットの亡霊」の「意識を解き放つ」に、顔のある相手を与えるためである。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| 主人公が自分で企業の装置を乗っ取った | 毎周迎えてくれる人物がいなくなる。意識を抜き取られた主人公が、なぜその腕を持っていたかの説明も要る |
| 企業がわざと主人公を自由にさせている（実験の一部） | 主人公の選択がすべて企業の手の内になり、エンディングの選択の重みが減る |
| 生き直しの理由を説明しない | 依頼の出発点が、この理由づけである（issueの元になったスレッド） |
| 記憶ポイントを企業からの報酬とする | 企業に逆らう周でも同じように手に入る理由が付かない |
| 人物を1人（ミオ）だけにする | 断片「名前」の昔の仲間と、エンディング「ネットの亡霊」の相手に、顔が無いままになる |

## 影響

[DOM-09](../20-domain/dom-09-consciousness-copy.md)と[DOM-10](../20-domain/dom-10-characters.md)ができる。[DOM-01](../20-domain/dom-01-world.md)から両方へ案内を置く。

ゲームのデータと実装は変わらない。画面の文（転生の画面・永続強化の説明・記憶の断片の文）に人物と理由づけを入れることは、別のissueで行う。

## 見直しの条件

人物を画面に出したときに、台詞の量が多すぎて周の流れを止めると感じたら、出し方を見直す。人物を5人以上にしたくなったら、DOM-10の不変条件を見直す。
