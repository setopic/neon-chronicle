# 4つの勢力に評判を持たせ、周をまたいで残す

- 日付: 2026-10-20
- 状態: stable

## 背景

8つの勢力（[DOM-15](../20-domain/dom-15-city-places-and-powers.md)）は、資料と地図に出るだけで、遊びに効いていなかった（issue #84）。下層街を舞台にしたイベントには、屋台組合とザンダー・ファミリーのどちらかに付く選択肢がすでにあったが、選んだことは周が終わると消えていた。

issueでは、評判を持つ勢力と、上下する選択肢と開くもの、周をまたいで残すか、クロニクルの文に出すかの3つを決めることにしていた。作者からは、推奨の案で進めてよいと言われている。

## 決定

1. 評判を持つ勢力は、ザンダー・ファミリー・屋台組合・ヨミ・システムズ・ヴァルデック義体の4つにする。値は`game/data/factions.json`に置く。
2. 評判は-10から10までの整数で、始めは0とする。
3. イベントの選択肢に、評判の増減を付ける。既存の8つのイベント（薬の配達・合成食の荷運び・保護料の運び・闇市場の買い手・変電所の奪い合い・盗電の線・偽の身元・遺体の取り立て）の選択肢に、内容に合わせて-2〜+2を付ける。
4. 評判で開くのは、評判の条件を持つ選択肢とする。4つの勢力ごとに1つ、評判3で選べる選択肢を既存のイベントに足す。
5. 評判は転生しても残す。最初からやり直すと0に戻る。
6. クロニクルの文には出さない。体の状態の欄に、0でない評判を1行で出す。選択肢のボタンに、評判の増減と評判の条件を出す。
7. 評判の条件は選ぶ条件の1つとして扱い、縛り「安全な選択肢を選ばない」でも、選ぶ条件のある選択肢に数える。
8. 評判は、新しいドメインノード[DOM-22](../20-domain/dom-22-faction-reputation.md)に書く。

## 理由

4つの勢力にしたのは、すでにあるイベントで主人公と関わる勢力がこの4つだからである。モンフォール警備・リンドホルム食品・下層街の住人・路地のごろつきは、イベントで関わっても、選択肢で付く側が分かれない。

評判を残すのは、どの勢力と付き合ってきたかを周回の積み重ねにするためである。周ごとに戻すと、評判3に届く前に周が終わることが多く、開く選択肢を選ぶ場面がほとんど無くなる。

開くものを選択肢にしたのは、イベントの結果を決まった量にする決まり（[ADR-0004](./adr-0004-event-rules.md)）をそのまま使えるからである。稼ぎや経験の効果にすると、永続強化と同じ働きになり、釣り合いを決め直すことになる。

クロニクルの文に出さないのは、記録の物語文が、選んだ選択肢の句でもう勢力との関わりを表しているからである（[ADR-0005](./adr-0005-chronicle-story.md)）。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| 8つの勢力すべてに評判を持たせる | 4つの勢力は、選択肢で付く側が分かれず、評判が動かない |
| 評判を周ごとに0へ戻す | 評判の条件に届く前に周が終わり、開く選択肢を選べない |
| 評判で、稼ぎや経験の効果を出す | 永続強化と同じ働きになり、釣り合いを決め直すことになる |
| 評判が下がると、仕事に就けなくする | 仕事に就けないと周が進まず、取り返しが付かない |
| 評判をクロニクルの文に出す | 記録の物語文が、選んだ選択肢の句でもう関わりを表している |
| 評判の上限を設けない | 開く条件の値を、周を重ねるほど上げることになる |

## 影響

DOM-22を新しく起こし、評判・評判の増減・評判の条件を定義する。

`game/data/events.json`の選択肢に`reputation`と`requires_reputation`を足す。`game_state.gd`は評判を転生しても残る状態として持ち、セーブに書く。前の版のセーブは、どの評判も0として読む。体の状態の欄と、選択肢のボタンに評判を出す。`playthrough.gd`は、評判の条件を満たした選択肢も選べるものとして扱う。

## 見直しの条件

評判で開くものが少なく、評判を気にせずに遊べてしまうようになったら、評判の条件を持つ選択肢か、評判で開く仕事を足す。勢力どうしの対立を話にするとき（issue #85）は、評判の使い方をそちらで決める。
