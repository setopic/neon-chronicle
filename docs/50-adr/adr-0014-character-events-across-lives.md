# 人物のイベントを1周に1段ずつ進め、前の段の選択で文と選択肢を変える

- 日付: 2026-10-18
- 状態: deprecated（[ADR-0043](./adr-0043-mio-character-events.md)が置き換えた）

## 背景

イベントは周ごとに独立していて、周を重ねても人物との関係が進まなかった（issue #38）。[DOM-10](../20-domain/dom-10-characters.md)では、ミオ・ジン・レイ・九条の4人を決めている。周をまたいで話が進むイベントがあれば、周を重ねる楽しみになる。

issueでは、どの人物のイベントをいくつ足すか、話の進み具合を転生しても残る状態としてどう持つか、前の選択を後のイベントにどう反映するかの3つを決めることにしていた。

## 決定

1. 人物のイベントは、レイとジンの2人に3段ずつ、合わせて6つ足す。レイの段はハッカーの仕事で起き、ジンの段は運び屋と傭兵の仕事で起きる。
2. 人物のイベントは、ふつうのイベントと同じ`game/data/events.json`に置き、イベントに人物のidを持たせる。同じ人物のイベントは、並んだ順を段の順とする。
3. 1つの周で進むのは、人物ごとに1段までにする。起きうるのは人物の次の段だけで、ほかのイベントと同じ確率で選ぶ。
4. 話の進み具合は、人物のイベントで選んだ選択肢を、イベントのidごとに持つ。転生しても残り、最初からやり直すと無くなる。
5. 前の選択は2つの形で後の段に反映する。1つは説明の文の書き分けで、前の段で選んだ選択肢ごとに、言語ファイルに`event.<id>.desc.<選択肢>`を置く。もう1つは前の選択の条件で、前の段で決まった選択肢を選んだときだけ出る選択肢を置く。条件を満たさない選択肢は、選び直せないので画面に出さない。
6. ジンの3段目は、記憶の断片「名前」が戻るまで起きない。そのため、イベントに要る断片を持たせる。
7. 人物のイベントは、新しいドメインノード[DOM-13](../20-domain/dom-13-character-events.md)に書く。DOM-10の「画面に出るところ」に、レイとジンの人物のイベントを足す。

## 理由

レイとジンにしたのは、2人とも仕事の間に主人公と関わるからである。イベントは仕事の間にしか起きない（[DOM-06](../20-domain/dom-06-events.md)）。ミオは診療所で主人公を迎える人物で、仕事の間には出ない。九条が姿を見せるのは最後の仕事の間だけと決めている（DOM-10）。レイは前の周を覚えている被験体で、ジンは主人公を毎周初めて会う相手として扱う。周をまたぐ話の書き方が2人で異なり、両方を試せる。

1つの周に1段までにしたのは、段が周をまたいで進むことを確かにするためである。制限が無いと、長く生きた周に3段が続けて起き、周をまたいで進む話にならない。段の数を3にしたのは、レイの段が仕事の間に出ることと、1周の長さ（数分）を合わせると、エンディングまでの周の数（数周から十数周）で話を終えられる量だからである。

話の進み具合を選んだ選択肢として持つのは、段がいくつ進んだかと、前の段で何を選んだかを、同じ1つの値から読めるからである。

前の選択の条件を満たさない選択肢を出さないのは、選び直す手段が無いからである。スキルのレベルの選ぶ条件は、レベルを上げれば満たせるので、満たさなくても画面に出して条件を見せている。前の選択はもう変えられないので、出しても選べない選択肢が増えるだけである。

ジンの3段目に要る断片を持たせたのは、ジンが主人公に気づくのは記憶の断片「名前」が戻ったあと、とDOM-10の不変条件で決めているからである。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| ミオの人物のイベントを足す | ミオは診療所の人物で、仕事の間に起きるイベントには出せない |
| 九条の人物のイベントを足す | 九条が姿を見せるのは最後の仕事の間だけと決めている |
| 1つの周で何段でも進める | 長く生きた周に話がまとめて進み、周をまたぐ話にならない |
| 人物のイベントをほかのイベントより起きやすくする | 起き方の決まり（ADR-0004）を人物のイベントだけ変えることになる。同じ確率でも、数周のうちに次の段が起きる |
| 話の進み具合を、人物ごとの段の数とフラグの組で持つ | 選んだ選択肢から段の数もフラグも読めるので、同じことを2か所に持つことになる |
| 前の選択の条件を満たさない選択肢を、選べない形で出す | 選び直す手段が無く、選べない選択肢が増えるだけである |
| 人物の一覧をデータのファイルに置く | 人物のidは名前の表示に使っておらず、イベントに持たせれば足りる |

## 影響

DOM-13を足し、DOM-10の「画面に出るところ」の表を直す。`game/data/events.json`に6つのイベントを足し、言語ファイルにその名前・説明・選択肢・物語の句・倒れたときの句を足す。

周の状態に、その周に人物のイベントが起きた人物を足す。転生しても残る状態に、話の進み具合を足す。#38より前のセーブは、人物のイベントが1つも起きていないものとして読む。`game/ci/check_data.py`は、説明の書き分けと前の選択の条件が、同じ人物の前の段を指しているかを確かめる。`game/ci/characters.gd`が、段の順・1周に1段・文と選択肢の変化・最初からやり直したときの戻り方を確かめる。

人物のイベントを足すMODは、`events`に`character`を持つ項目を足す。前の段で書き分けるなら`desc_by`を、前の選択の条件なら選択肢に`requires_choice`を書き、言語ファイルに書き分けた説明を置く。

## 見直しの条件

人物のイベントが起きなさすぎて話が進まないという声が出たら、起きやすさを決め直す。レイかジンの話をエンディングの文に反映したくなったら、話の進み具合をエンディングの側から読む決まりを足す。
